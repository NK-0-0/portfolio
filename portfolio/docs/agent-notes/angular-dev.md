- Running `npx @lhci/cli autorun` locally (M4.5 a11y): this sandbox has NO system Chrome → LHCI healthcheck fails "Chrome installation not found". Fix: point it at the Playwright-bundled chromium via env — `export CHROME_PATH="$HOME/.cache/ms-playwright/chromium-1223/chrome-linux64/chrome"` (the `chrome` binary, NOT `chromium_headless_shell`), and pass `--collect.settings.chromeFlags="--no-sandbox --headless=new"`. Then it collects normally against `staticDistDir`. Read scores from `.lighthouseci/lhr-*.json` (`.categories.accessibility.score`, `.audits["color-contrast"].score`) — the CLI summary only prints pass/fail vs the `lighthouserc.json` assertions, not the numbers. NOTE the `chromium-1223` version dir will bump with playwright upgrades — `find ~/.cache/ms-playwright -name chrome -type f` to get the current path.
- `:focus-visible` (not `:focus`) is the correct global focus-outline selector, AND it's what Playwright verification requires: `:focus-visible` only matches keyboard-initiated focus, so you MUST drive it with `page.keyboard.press('Tab')` — a programmatic `element.focus()` will NOT trigger `:focus-visible` and your outline assertion will spuriously fail. A single global `:focus-visible { outline: 2px solid var(--color-accent); outline-offset:2px }` in styles.scss covers all 11 focusable elements (5 skip-nav + scroll-cue + 2 project links + 3 contact links); the old per-component `.sr-nav__btn:focus` was redundant once the global rule existed.

- Cross-browser Playwright matrix (M4.7): adding `webkit`/`firefox` projects to `playwright.config.local.ts` is trivial (`devices['Desktop Safari']`/`['Desktop Firefox']`), but `npx playwright install webkit firefox` DOWNLOADS the browsers yet WebKit still won't LAUNCH in this sandbox — needs system libs (`libicu74 libwoff1 libenchant-2-2 libavif16 libmanette-0.2-0 libflite1 libxml2`) only installable via `sudo apt`/`playwright install --with-deps`, which the sandbox can't do. Firefox + Chromium launch fine unaided. So exercise `--project=chromium --project=firefox` locally and rely on CI's `ubuntu-latest` + `npx playwright install --with-deps` for WebKit — config it, document the local gap, don't block on it.
- FPS/frame-timing gate (M4.7): sandbox headless Chromium has NO GPU → SwiftShader software WebGL → the scroll-through measures ~8fps (p95 ~200ms), NOT representative of real hardware. So do NOT commit a locally-captured `baseline.json` — a 200ms baseline makes the +15% gate dead (never fires). GitHub `ubuntu-latest` ALSO has no GPU (also software-renders), so let the first CI run establish+commit the baseline in the environment that'll run the gate (script logic: no baseline → write+pass; else compare+gate). rAF sampling recipe that works: `addInitScript` a self-perpetuating `requestAnimationFrame` collector into `window.__frameTimes`, wait for canvas visible + settle, then `evaluate(()=>{window.__frameTimes.length=0})` to DISCARD load-time jank before driving the scroll — measure only the motion. Gate on p95 (jank), not mean (hides hitches). Drive the scroll via the existing `button[data-section]` skip-nav (reuses M4.4's hook), dwell ~1200ms/section for Lenis+GSAP.
- `.section-card--visible` is a PHANTOM class — it exists nowhere in `src/` (neither this branch nor `main`; `grep -rn section-card--visible src/` = 0), only in the prod e2e spec (`e2e/portfolio.spec.ts:123`) as a `toHaveClass` assertion. The scroll-layout card reveal is a pure GSAP entrance (`gsap.set(el,{opacity:0,...})` → `gsap.to(el,{opacity:1,...})` on ScrollTrigger `top 76%`), class list stays `section-card section-card--left/right`. So the prod suite's 5 scroll-nav tests are latently broken against ANY correct build of current `main`, independent of the live-site-staleness story the qa-engineer log tells — don't copy that assertion. Assert reveal via computed opacity instead: `expect.poll(() => Number(getComputedStyle(card).opacity)).toBeGreaterThan(0.9)` (pre-reveal is opacity:0). Skip-nav (`scene.component.ts` `scrollTo`) uses native `scrollIntoView({behavior:'smooth'})`, NOT hash nav.
- A literal `*/` inside a JSDoc/`/* */` block comment in a `.ts` Playwright *config* silently closes the comment early → Playwright's babel loader dies with a cryptic `BABEL_PARSE_ERROR: MissingSemicolon` pointing at the NEXT real statement, not the comment. Bit me writing `namespaced under */local/` in playwright.config.local.ts's header. Line (`//`) comments are immune — only block comments. Never write a bare `*/` (e.g. a glob) inside a block comment.
- Local pre-deploy e2e (M4.4): Playwright `webServer.command` can do build+serve in one shot (`ng build --configuration production && npx http-server dist/portfolio/browser -p 4173 -s -c-1`), with `timeout: 180_000` (a cold prod build > the 60s default) and `reuseExistingServer: !process.env['CI']`. Keep the npm script to just `playwright test --config=...` so the build isn't run twice. Playwright's bundled headless chromium DOES render real WebGL here (SwiftShader) → `DeviceCapabilityService` stays in `'3d'` mode (no `--use-gl` flags needed for the built app, unlike a raw dev-server driver), so the local suite can require 3d and fail loud instead of silently skipping like the prod suite does.

- Spec-writing gotcha: `ComponentFixture.nativeElement` is typed `any`, so a generic DOM call like `nativeElement.querySelectorAll<HTMLElement>('.x')` fails the prod build with `TS2347: Untyped function calls may not accept type arguments` (specs are type-checked by the same angular-compiler). Cast the root once: `const root = fixture.nativeElement as HTMLElement;` then `root.querySelectorAll<HTMLElement>(...)`. The existing about/contact specs sidestep this by never passing a type arg (they let `.forEach((a) => ...)` infer via an annotated `NodeListOf<HTMLAnchorElement>` on the LHS).
- Testing a browser-only component whose GSAP/Lenis (or any `afterNextRender`) init you DON'T want to run: mount it with `providers: [{ provide: PLATFORM_ID, useValue: 'server' }]`. `afterNextRender`/`afterRender` are documented no-ops on the server, so the whole browser-init path (Lenis ctor, `ScrollTrigger.create/refresh`, and every `viewChild.required()` read inside it) never fires, yet the template still renders fully — lets you assert the DOM/routing contract (e.g. scroll-layout's ordered section ids) without mocking the scroll pipeline. Used for `scroll-layout.component.spec.ts` (M4.2). Corollary: the pure hash→index logic already lives in `sectionIndexFromHash` (section.types.spec.ts), so there was no value in driving `#applyHash` end-to-end through a mocked Lenis+GSAP+afterNextRender stack.

- Lenis@1.3.23 hash deep-linking: `lenis.scrollTo(target, opts)` confirmed against the installed `node_modules/lenis/dist/lenis.d.ts` — `opts.immediate: true` snaps (reduced-motion/on-load path). BUT do NOT pass a `#id` selector string for a *hash-triggered* scroll: setting `window.location.hash` fires the browser's native scroll-to-anchor, which momentarily desyncs `element.getBoundingClientRect().top` from Lenis's internal `animatedScroll`; Lenis's selector path computes `rect.top + animatedScroll` and lands on the WRONG (stale) section (verified: nav to `#contact` stuck at `#about`'s offset, activeSection reverted). Fix: pass a scroll-independent absolute doc offset (`offsetTop` chain up `offsetParent`) as a number — immune to the transient native-jump state. `immediate` scrollTo is unaffected (only animated selector scrolls desync). `hashchange` alone covers anchor clicks AND back/forward hash nav (no separate `popstate` listener needed).
- Reduced-motion (FR-8) has no central service in `src/` as of M3 — a self-contained `window.matchMedia('(prefers-reduced-motion: reduce)').matches` check (isBrowser-guarded, evaluated at call time so it stays live) is the right lightweight wire-in for a single feature; don't build a service for one consumer (YAGNI).

- HDRI env-map wiring in three@0.182: `RGBELoader` is now `@deprecated` (it's a bare `extends HDRLoader` with no body in `@types/three`) — use `HDRLoader` from `three/examples/jsm/loaders/HDRLoader.js` instead (same `DataTextureLoader.load(url, onLoad)` signature, returns a `DataTexture`). Standard PMREM recipe: `const p = new PMREMGenerator(store.snapshot.gl); p.compileEquirectangularShader(); new HDRLoader().load('env/x.hdr', tex => { tex.mapping = EquirectangularReflectionMapping; scene.environment = p.fromEquirectangular(tex).texture; tex.dispose(); p.dispose(); })`. Keep the returned `WebGLRenderTarget` to `.dispose()` in `ngOnDestroy` (+ `scene.environment = null`). Path is relative w/ NO leading slash so it resolves against `<base href>` (=/portfolio/ in prod), same as the old GLB loader convention. This is NOT a GLB — do not touch `ModelLoadingService.TOTAL_ASSETS`. `store.snapshot.gl` is the `WebGLRenderer`; `store.snapshot.scene` the `Scene` (types: angular-three.d.ts ~L630/634). `PMREMGenerator`/`EquirectangularReflectionMapping` are core `three` exports.

- Deleting the last GLB (fully procedural scene) removes `public/models/` entirely, and `scripts/check-glb-budget.mjs` did an unguarded `readdirSync(MODELS_DIR)` → CI would crash with `ENOENT` on a *clean* repo. When you remove the last thing a script globs, guard the walk root with `existsSync` and no-op-pass. Also drop the script's `EXCEPTIONS` set the moment the exempted file is deleted, or the gate silently keeps trusting a name that no longer exists.
- This repo's interactive shell profile aliases `rm` to `trash` (not installed) — a bare `rm` inside Bash tool calls dies with `trash: command not found` (exit 127) and does NOT delete. Use `/usr/bin/rm` for scratch files, and `git rm` for tracked ones. (`@playwright/test` re-exports `chromium`, so `import { chromium } from '@playwright/test'` works without a separate `playwright` dep.)

- HDRI budget vs. Poly Haven reality: the ASSET_PIPELINE `< 512KB` HDRI budget is real but Poly Haven's *smallest* `.hdr` is 1k (a pure-sky night is ~1.3MB), so a straight download busts the budget — you must downsample. This machine has NO imagemagick/PIL/imageio/cv2, but `oiiotool` (OpenImageIO 3.1.x) IS installed and handles Radiance HDR: `oiiotool in.hdr --resize 512x256 -o out.hdr` (HDRIs are 2:1 equirect, so 512x256 keeps aspect). 1k→512px took a pure-sky night to 355KB, header stays `#?RADIANCE`. No gltf-transform needed for HDRIs.
- Working on a branch while a *concurrent* agent holds uncommitted changes in the SAME working tree: do NOT `git checkout -b` — it moves HEAD out from under them and their later commits land on your branch. Use `git worktree add -b <branch> <sibling-path> main` instead (fully non-disruptive; their tree/branch/uncommitted files untouched). The worktree has no `node_modules` (gitignored), which is fine for file-only/doc tasks that don't build; the new branch is still visible + mergeable from the main repo.
- Headless visual verification of a 3D change: drive the running dev server with Playwright, but two gotchas. (1) The `playwright` package only resolves from `portfolio/node_modules`, so a `.mjs` driver in the scratchpad fails `ERR_MODULE_NOT_FOUND` — write/run the script from inside `portfolio/` (delete after). Assert `app-fallback` count is 0 and a `<canvas>` exists to confirm you're actually looking at the WebGL scene, then `scrollTo({behavior:'instant'})` + screenshot per beat.
- `beforeRender` (the non-deprecated angular-three@4.2.2 callback) is a literal alias of `injectBeforeRender` — `declare const injectBeforeRender: typeof beforeRender` (types line ~1863). Same signature, same `({ delta }) => {}` state arg; migrating a component is a pure rename, no behavioral difference. Procedural props (no GLB) don't need `injectLoader`/`loaderResource` at all — build the `Group`/meshes imperatively in the constructor (browser-guarded), expose via a `signal<Group|null>`, and render with `<ngt-primitive *args="[group()]" />` (still needs `NgtArgs` imported for `*args`).
- `@angular/router` is NOT a dead dependency despite the app defining no routes — `angular-three@4.2.2` statically imports it (`import * as i1 from '@angular/router'` for `NgtRoutedScene`) at the top of its fesm bundle, and does NOT declare it in peerDependencies. Removing it from package.json passes `npm install` but breaks `ng build` with `Could not resolve "@angular/router"`. Keep it installed; you can still drop `provideRouter`/`app.routes.ts` since `NgtRoutedScene` is never instantiated (this app uses `NgtCanvas` from `angular-three/dom`).
- `ng test --run` does NOT exist in the Angular 21 `@angular/build:unit-test` (Vitest) builder — errors `Unknown argument: run`. Use `ng test --no-watch` (watch also defaults to false in non-TTY/CI). CLAUDE.md/docs historically wrote `--run` (a Vitest-CLI-ism); it's wrong. Use `--no-watch` in CI workflows.
- Re-adding a removed `@angular/*` dep with a caret (`^21.2.0`) makes npm resolve the newest patch (e.g. router 21.2.17), whose peer wants `@angular/core@21.2.17` while the rest of the workspace is pinned to 21.2.15 → ERESOLVE. Fix: `git checkout -- package-lock.json` then `npm install` so npm honors the already-locked compatible version instead of bumping.
- `@gltf-transform/cli@4.4.1`: the `optimize` flag is `--texture-size <px>`, NOT the older `--texture-resize` shown in ASSET_PIPELINE.md (errors `Unknown option`). `--texture-compress ktx2` shells out to the external KhronosGroup `ktx` binary (KTX-Software) — fails at the `uastc` step if not on PATH. Fallback `--texture-compress webp` needs no external binary (smoke test: mask 2.91MB → 98KB).
